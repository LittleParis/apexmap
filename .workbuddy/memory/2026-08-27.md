## 赛季数据源改造：官方 EA 页面优先（用户确认方案）

用户提出"赛季时间应调用官方接口 + 本地预估兜底"。核实：**EA/Respawn 官方没有公开赛季 API**，官方 help.ea.com 页面只公布开始日期，不公布当前赛季结束日期（S31 时间官方答复"请查看 ea.com"）。第三方 apexlegendsstatus 在赛季中段 startTime 指向 split 2，不可靠。

### 新架构（已实现并验证）
```
前端 useSeasonData
 ├─ 本地兜底（seasons.ts：官方开始日期 + 91 天预估结束）→ 主数据
 └─ /api/season（远程校验/更新）
     ├─ 官方 help.ea.com/en/...（权威）→ 赛季名+开始日期+赛季号
     ├─ 降级 apexlegendsstatus.com（可选）
     └─ server 端再降级本地硬编码
```

### 修改文件
1. `functions/api/season.ts`（重写）— 官方优先 + 第三方降级。官方解析：h2 "What’s new in Apex Legends: X"（注意 **Unicode 弯引号 ’ U+2019**）→ 赛季名；"the newest Season ... launches on Aug 4, 2026" → 开始日期（按 17:00 UTC 惯例）；h3 "(Season N)" 历史列表最大号 + 1 → 当前赛季号
2. `server/src/services/season.ts`（新建）— 同逻辑：官方 → 第三方 → 本地硬编码（S30 fallback 已内置）
3. `server/src/index.ts` — /api/season 改为调用 getSeasonInfo()（async）

### 验证结果
- server tsc / client tsc 通过
- 端到端：启动 server 后 `GET /api/season` 返回 `{"number":30,"nameEn":"Marked","countdownTs":1785862800}` ✓（官方解析）
- 官方解析输出：nameEn="Marked", startTs=1785862800 (2026-08-04T17:00Z), current=30 ✓
